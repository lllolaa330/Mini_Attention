# 自检平台与证据范围

## 软件参考

`model/attention.py` 包含两个用途不同的参考：

- `bit_model`：调用固定版本 SoftFloat 的 FP16 运算，按 PROJECT.md 指定顺序生成 16-bit 期望输出。`bit_model_with_probabilities` 同时返回 Y 和显式概率矩阵 P，两者以行优先排列；仿真可直接检查每次整行概率写回。CPU 模型与 RTL 共有舍入契约。
- `reference`：将同一组已量化 FP16 输入解码后，用 Python binary64 和稳定 Softmax 计算数学注意力。它不采用逐步 FP16 舍入或指数 ROM，用于报告精度损失。

独立的软件行级检查用 `math.exp`、两个指数项构成的递推以及显式 binary16 舍入重算 P，覆盖 81 帧、20,736 个概率，并核对各帧的独立 float64 注意力误差。[软件检查与复现命令](../results/online_os_model_20261118_150046_nelJ/summary.json)

逐位模型使用规范指数表，RTL 使用同一内容初始化 ROM。为了避免两者共同使用错误表而自洽通过，额外执行：19,542 项 Decimal 80/110 位重新计算、binary64 `math.exp` 独立公式比对、次正规/下溢门限检查。指数零门限 `0x4c56` 的相邻两点分别产生最小次正规数和零。

## 浮点算术与阵列单测

`make arithmetic` 对 FMA、add、sub、mul、div 运行 SoftFloat 生成的定向和随机向量。包括正负零、次正规数边界、极值、舍入及除法复位中止恢复。非法注意力输入导致的 NaN 算术用例只比较 NaN 分类，其他向量比较精确 bit pattern；因此不可把该单测描述为 NaN payload 的逐位一致性认证。完整注意力仅接受有限 [-2,2] 输入，所有输出均要求严格逐位一致且有限。

OS 阵列单测可选 `--size 2` 或 `--size 16`，内积长度均为 16，检查：

- 边界错拍和邻接传递，输出与顺序 SoftFloat FMA 比较。
- `step=0` 的保持；恢复后数据配对和累加结果仍正确。
- `clear` 相对 step 的优先级，以及异步复位。
- 无效但带有干扰数据的链路不更新累加值。
- 多个矩阵依次执行，不遗留前一轮结果。

历史 WS 阵列的独立单测通过 `make array DATAFLOW=ws` 调用。WS 的 2×2 和 16×16 阵列分别映射 2 项和 16 项内积。单测分别通过逆序移位、指定行地址两种方式装入同一组权重，再以 SoftFloat 顺序 FMA 检查输出。定址装载还检查目标行隔离、清零或暂停时写权，以及 FMA 与写权同拍时使用旧权重、下一拍使用新权重。

这不是形式化证明，覆盖范围由归档向量确定。

## 端到端仿真

`scripts/run.py` 编译 `rtl/files.f` 中的真实 RTL，testbench 驱动 binary16 数据流并逐字检查 256 个输出。每次输入/输出在时钟上升沿握手，testbench 在下降沿驱动；计数在下降沿更新，以避开激励、采样和 NBA 更新之间的竞争。

向量文件按 Q、K、V 顺序保存 768 个 FP16 字，三个矩阵各自行优先。每次输入握手传 16 个 FP16，通道 k 占 `in_data[16*k +: 16]`。Q 的第 i 行从 `words[16*i+k]` 取数，K 的第 j 行从 `words[256+16*j+k]` 取数，V 的第 j 列从 `words[512+16*k+j]` 取数。每帧输入共 48 次握手。

输入和输出使用独立的驱动器。主测试前四帧由发送端连续供数、接收端持续就绪，输入按 DUT 的 `in_ready` 前进。随后按参数插入输入气泡和接收端背压。压力用例在首组结果处持续阻塞 2,500 拍，并在中间、末尾及随机位置注入背压。检查整组数据、掩码及 last 在停顿时保持，同时检查下一帧输入握手与前帧输出握手重叠、QKᵀ 和 Softmax 各自与同一帧 V 输入握手重叠，以及 PV 运行期间第一次输出握手。

归一化的每次请求带行号，返回 16 个概率及同一行号。整帧按顺序发出和返回 16 行；无停顿时每拍一行。若阵列因流控而暂停，归一化可出现请求气泡，每次请求仍在 3 拍后返回。每个返回的 P 均与所属帧的 `expected_p.hex` 逐字比较。记录首末请求、首末返回的拍号，以及最后一个 QKᵀ 乘加和第一个 PV 乘加的拍号。

共享阵列的重叠证据取各 PE 的 `step && a_valid_in && b_valid_in`。从复位后第一个点积起，对每个 PE 连续分组计数，第 0–15 项对应第 0 帧 QKᵀ，第 16–31 项对应第 0 帧 PV，后续按帧重复。帧 n 的输出尚在传输时，部分 PE 已开始帧 n+1。统计各帧时须在相应 PE 本地按帧和阶段归属，不能在整帧输出握手时统一清计数。在 `partial_v` 测试中，接收端阻塞前帧输出时，经正常输入接口将下一帧的 Q/K/V 全部写入另一帧槽；对这帧要求存在 QKᵀ 与 PV 的真实同拍乘加。定向测试在 `out_valid` 为 1 且不同帧槽的 QKᵀ、PV 正在同拍推进时复位，还覆盖缺 V、归一化发出或返回、PE 乘加及输出末组受阻等复位点。均在复位后重新传入完整数据并核对结果。

`actual.txt` 逐行记录 run、case、行优先元素编号、FP16 编码和实测握手周期。同一握手的多个列通道共用周期。软件按 31 条对角线及各组内的列序检查每个记录，恢复 16×16 矩阵后逐位比较，并对独立 float64 参考计算每帧 RMSE 和最大绝对误差。阈值分别为 0.06 和 0.20。

首输入、首输出和末输出均按有效握手采样。两个延迟分别用首输出或末输出周期减首输入周期再加一。在连续批次内分别计算相邻帧首输入、首个 QKᵀ 乘加和首输出的周期差。全速条件下检查相邻 QKᵀ 与相邻首输出均相隔 52 拍，以及相邻帧有 30 拍同时执行真实乘加。双帧缓冲初始连续接收两帧，稳态再检查相邻首输入间隔。不同复位批次独立计数。[连续六帧波形与逐帧计数](../results/frame52_top_20261118_9myellui/matched/comparison.json)

`--single-frame` 是波形观察入口，只保留第一组输入和一次启动复位，不执行复位恢复套件。配合 `--stalls 0 --waves` 生成单次无气泡、无背压的完整 Attention。仍检查输出、握手、done 脉宽、超时、精度和完成后 20 拍空闲；该模式不作为复位、随机气泡、背压及连续帧覆盖的通过证据。testbench 的 `SINGLE_FRAME` 参数默认关闭，常规回归行为不变。

`checker_selftest.py` 在新目录复制通过版本的输入和期望输出，将第一个期望字 XOR 1，复用该本地运行的仿真程序。只有非零退出且报告指定第一元素 `BIT MISMATCH` 才通过；其他报错不视为成功。

## 从波形比较 PV 停顿和 PE 利用率

PV 窗口从首个有效 PV 步至末个有效 PV 步，含两端。在该窗口内逐个采样上升沿前的 `dut.pv_step`，为 0 的拍计入空闲。对齐 `v_ready`、`p_ready` 和 `wave_slot_available` 可观察缺 V、概率行未就绪或输出缓冲已满。第 i 行第 j 列的有效乘加由 `tb_attention.pe_mac[16*i+j]` 在上升沿前取样。跨帧重叠期间，在 PV 窗口内还可能有下一帧的 QKᵀ，须按帧把同一物理 PE 的乘加分别归属。数值为零的有效乘加同样计入。

报告每个 PE 的**计算窗口利用率**时，从首个 QK 乘加数到末个 PV 乘加，包含两端，分子为该 PE 在窗口内的有效乘加数。报告**端到端利用率**时，同帧的 32 次有效乘加除以首个输入握手至末个输出握手的拍数。两种输入接口应使用相同矩阵、相同输出组背压规则，并分别记录各自的输入握手数。

## 两种延迟的重放对照

本节重放此前双帧缓存 OS/WS 基线的优化前、后 RTL；其中两版均采用历史加法树分母，所用归档期望值对应当时源码。两版使用同一组全零、转置探针、随机位模式、均匀随机输入，对每帧 31 个输出组的掩码、帧尾和全部 256 个 FP16 字进行检查。期望值来自 SoftFloat，另外与独立 float64 参考比较误差。[逐帧结果](../results/v_overlap_20261118_120306/benchmarks/comparison.json) · [夹具校验](../results/v_overlap_20261118_120306/fixture_verification.json)

- **流式输入**。四帧经顶层接口连续发送，每拍提供一个字，下游持续就绪。本帧第一次输入握手记作第 1 拍，可测首组输出延迟、末组输出延迟和相邻帧的输入 II。
- **片上预装**。每帧先复位，仿真夹具将 Q/K/V 写入第 0 号帧槽，设置对应的 QK 就绪与整槽有效位。核心从 `LOAD` 派发，`CLEAR_QK` 的上升沿记作第 1 拍。首组和末组输出均以实际握手为终点。各帧独立预装，该口径的输入 II 记为空。

重放时从仓库根目录执行下列命令，`replay_1` 用作本次输出目录。每个版本与数据流组合只编译一次，两种口径复用该仿真程序。[重放脚本](../results/v_overlap_20261118_120306/benchmark.py)

```sh
cd results/v_overlap_20261118_120306
for version in before after
do
  for flow in os ws
  do
    python3 benchmark.py --root-out replay_1 --variant "$version" --flow "$flow"
  done
done
python3 benchmark.py --root-out replay_1 --compare
```

每组的 `schedule.csv` 逐拍记录第 0 帧的上升沿前状态，包括 V 输入、权重行装载、`array_step` 和输出掩码。`timing.csv` 给出四帧各自的起点、首末输出周期以及流式输入 II。早期的 [OS / WS 流水时间线](../results/stream_timeline_20261118/timeline.json) 记录的是等待整帧 V 的版本，该版本在本次对照中作为 `before`。

## 运行目录

| 文件 | 证据 |
|---|---|
| `manifest.json` | 命令、参数、工具版本、Git 状态、源码 SHA-256、运行状态 |
| `cases.json` | 768 字输入、位模型期望输出和 float64 数学参考 |
| `input.hex` / `expected_p.hex` / `expected.hex` | 各矩阵按行保存的原始输入字、期望 P 和期望 Y |
| `exp_fp16.hex` | 仿真采用的 ROM 副本 |
| `actual.txt` | RTL 输出、帧号、索引和周期 |
| `simulation.log` | 逐位与协议检查、复位和覆盖汇总 |
| `per_frame.csv` / `summary.json` | 逐帧误差和汇总 |
| 编译、模型、ROM 日志 | 执行命令及工具原始输出 |

各次运行使用独立目录，并保留失败日志。`results/release_iverilog_seed20261117` 和 `results/compact_wave_check_20261117` 使用旧版串行 Softmax，其期望值和复位次数对应旧版实现。核对任一运行对应的 RTL 和模型版本时，以 manifest 中的源码 SHA-256 为准。编译缓存和波形被 Git 忽略；新克隆后的复现需要重新编译。

## 验证不覆盖的事项

归一化流水线可连续接收新行。完整任务周期仍随 V 到达及输入输出停顿变化。testbench 的时钟周期只用于事件仿真，不是 STA 或 FPGA 运行频率。综合、存储映射、最高频率、面积、功耗、布局布线、板级运行和对所有合法输入的形式化证明均须分别开展；本项目的实际完成状态以 EXPERIMENTS.md 为准。
